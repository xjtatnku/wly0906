## DeepSeek 已真实接入

项目根目录 `.env` 自动读取，支持以下标准格式，也兼容本机目前仅一行密钥的格式。密钥不输出到浏览器、数据库或实验报告，`.env` 已被 Git 忽略。环境变量优先于文件；更改已加载配置后重启服务。

```dotenv
DISASTER_API_KEY=在本机填写
DISASTER_BASE_URL=https://api.deepseek.com
DISASTER_MODEL=deepseek-v4-flash
```

亦支持 `DEEPSEEK_API_KEY / DEEPSEEK_BASE_URL / DEEPSEEK_MODEL`。只把受支持字段当字符串解析，不执行 `.env` 中的命令或表达式。

本轮真实调用 `deepseek-v4-flash`：Chat Completions、`json_object`、关闭思考模式、30秒请求超时、2400最大输出token、无SDK重试。应用给出 Pydantic JSON Schema，并在收到JSON后做严格字段校验；**不是宣称服务端启用了 Responses JSON Schema 强制解码**。当前使用已核验的官方接口：[首次调用](https://api-docs.deepseek.com/zh-cn/)、[JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。

模型输出再校验地点是否在原文中、道路/资源/站点编号是否已配置且有原文、伤亡数字是否能在对应证据片段中核对。未明确地点和人数保留空值；不展示未经校准的置信度。调用失败、非法JSON或证据不符，会明确返回离线规则候选，仍需人工确认。

策略页面的“模型辅助解释”把检索到的条款与当前已验证派遣发给模型；只接受现有条款ID、原文子串及准确的资源/任务/到达时间。最终文字与数字由程序组织。它不是自由生成的因果故事；不让模型决定资源容量、可达性或编造节省分钟数。规则性条款仍需人工判断，不直接成为未经审核的硬约束。

**已经验收**：连接测试、两轮各50条真实抽取诊断、浏览器真实抽取及真实引用/分配说明。`configured=true` 仅说明本机有配置，不等同持续服务可用；实际调用结果单独标记成功或回退。

## 一个案例，九阶段事件链

策略页点击“重置并开始事件链”，然后逐次“准备下一阶段候选 → 核对/修改 → 批准”。准备阶段会推进既有执行和模拟时钟，但当前候选尚未提交；批准整个批次后统一重规划。拒绝仅写审计事件。

| 模拟分钟 | 阶段 | 变化 |
|---:|---|---|
| 0 | 灾前风险 | 人工确认的风险排序输入，考虑前置 |
| 5 | 首次灾情 | 失联8人、受伤3人，生成搜救/医疗 |
| 12 | 新增需求 | 新增失联5人，总数变13人 |
| 20 | 同时事件 | 道路中断 + 监测数据延迟 |
| 27 | 执行故障 | 优先选当前活动资源注入故障，解除未完成协同承诺 |
| 35 | 增援 | 已配置的待增援资源变为可用 |
| 42 | 次生风险 | 邻近区域风险排序升高与搜救需求 |
| 50 | 修正与二次封路 | 失联总数修正为15人，不再次相加；另一道路中断 |
| 65 | 趋稳恢复 | 物资与安置任务 |

阶段与人数全部是**康定背景下的模拟构造**，不写成历史事实。风险变化是有来源标签和30分钟有效期的人工情景排序覆盖，不改写环境原始观测、不伪称预测模型算出的值。数据延迟暂时截断指定站点可见窗口30分钟，暂停不完整联合输入驱动的前置；解除后恢复观测时钟回放。它不是现场网络延迟实测。

信息修正使用 `situation_reports` 与 `current_reports` 保存版本链，按地点保存目前确认总数；新增数需要先有基数。信息更正保留旧值和 `supersedes`，不自动重复生成任务。原文编辑、类型修改和执行仍由人确认。若要改变实际任务需求，必须明确勾写需求，不能从人数修正推测队伍数量。

批次校验和执行在同一状态锁内：道路/资源操作先不单独求解，整批处理后一次重规划和保存；失败恢复内存且不写入新批次快照。跨批次重复提交还需校验状态版本；相同分钟和原文的已提交批次不会二次累计。

## 调度与统计增量

调度页可切换“加权滚动”和“词典序滚动”。词典序依次最小化：P1未满足任务数、P1响应分钟、其他未满足任务数、行程＋λ扰动。所有方法沿用相同资源同步、路网、占用和执行锁定约束。

每层仅在 `OPTIMAL` 时固定值再进入下一层；出现 `FEASIBLE` 时保留可行解并停止，`UNKNOWN` 时优先用前一层可行解，无可行解才降级。四层分配同一轮总预算的剩余时间，不各自重新获得全额预算。`lexicographic_levels` 保存每层证明状态；`verified_lexicographic` 是程序重算向量，`verified_objective` 仍只是兼容的加权诊断值，不是词典序总目标。

| 数据 | 内容 |
|---|---|
| `results/v23/paired_statistics.csv` | V2.2旧960组的72项分格配对统计，10,000次bootstrap、平均/中位差、95%点区间、标准化效应、胜率和平局 |
| `results/v23/lexicographic.csv` | 20种子 × 3强度 × 5方法 = 300组新异构事件实验，资源比例固定50% |
| `results/v23/beta_sensitivity.csv` | 同20种子高强度下 β=0/1/2/5/10/20/50，共140组 |
| `results/v23/stress_repeated.csv` | 6类压力情景各30次，共180组，报告内存事件处理延迟的P50/P95/P99 |
| `results/v23/intake_records*.json` | 两轮真实API输出、校验状态、明确回退、规则结果和标签 |
| `results/v23/event_replay_traces.json` | 浏览器九阶段的状态与重规划证据 |

新增任务随机改变地点、类型组合、P1比例、发布时间和作业时长。中/高强度含资源故障，高强度另加二次封路，所有方法共享相同种子输入。结果不与旧960组拼接成同一实验族。`greedy` 明确指约束感知、优先级驱动的贪心；没有添加违反复合资源约束的弱贪心来制造优势。

配对置信区间是探索性的点态区间，未做多重比较校正。延迟重复测试不包含HTTP/SQLite/大模型网络开销；P99来自30次的小样本经验估计。响应、区域Gini需同时看未满足和未服务区域，不能只比较已经开始的容易任务。

压力实验混合工作进程首次初始化预测器和后续缓存命中；`delayed_sensor` 尾部包含冷启动成本，不代表稳定热启动延迟。配对胜率与平均差热力图均保存在 `results/v23/`。
