# V2.1 数据真实性与算法验证

定位：**面向自然灾害的动态态势感知与应急资源调度研究原型：基于真实案例背景、模拟在线数据与滚动优化的可复现实验系统。** 本机运行沿用 [V2启动说明](README-V2.md)，访问 http://127.0.0.1:8800 。没有接入真实传感器、车辆GPS、实时气象或实时封路。

## 本轮实现

1. 数据中心区分模拟时刻、观测时间、实际入库时间，展示FRESH/DELAYED/STALE/OFFLINE、观测年龄、接收间隔、缺失率和接收质量。
2. 预测页新增5/15/30/60分钟递归滚动起点评估，共48条指标。各时距使用相同验证起点，后续输入为模型自身预测。仍是S01四变量分别预测，没有实现空间预测或联合变量模型。
3. 调度页可切换“模拟基线”与“OSM道路快照”。切换重置当前演示并保留历史，原基线文件不改写。
4. 新P1任务、增援、风险等级变化、封路、人工确认和资源故障触发重规划，周期10分钟兜底；同刻原因合并求解并写日志。故障资源不再派遣，未完成协同作业需从头执行，已耗时保留。
5. 多步评估与稳定权重0/5/20/50/100敏感性实验写入 `results/v21/`，原 `results/v2/` 结果保留。

## 两套时钟与迁移

`observed_at`为带时区的观测时间；`received_at`由服务器记录实际UTC入库时间，客户端不能伪造；`received_minute`为仿真可见时间。查询同时要求观测和接收分钟不晚于当前模拟时刻。CSV启动时批量入库，其模拟接收分钟设为观测分钟，表示流式回放，不是硬件传输。

增加source_id/source_seq/quality_code/checksum/version。仍按站点/分钟/变量去重，不支持覆盖修订，version固定1；source_seq为模拟分钟，不是硬件流水号。

时效阈值为实验设定：观测年龄≤5分钟为FRESH，>5分钟为DELAYED，>15分钟为STALE；接收间隔>30分钟或无记录为OFFLINE。质量率来自有效观测、重复和拒绝计数；缺失率按近一小时13个五分钟采样点计算，不是气象部门质量评级。S01过期或缺口输入停止驱动预测前置，曲线仍展示并标记。

旧SQLite自动添加字段，保留数据和快照。旧记录实际接收时间保持空值，不补造历史；标记LEGACY_VALID，模拟接收时间按原观测分钟迁移。同一模拟分钟后续导入的数据尚无独立历史接收版本隔离；严格审计使用已保存的预测、计划和健康快照。

## OSM寻路

范围29.96—30.15°N、102.02—102.25°E。原始9,115个要素，构图后347节点、776有向路段。`data/v2/osm/manifest.json`保留查询、端点、快照与下载时间、SHA-256及许可。启动不联网下载，仓库快照可离线构图。

```powershell
# 可选更新：会改变路网，对比实验须固定manifest校验值
.\.venv\Scripts\python.exe scripts/fetch_osm.py
.\.venv\Scripts\python.exe -m disaster.v2.osm
```

从way/node构图，过滤明确禁止机动车/private道路，保留单行方向、-1与环岛默认方向。度2链压缩保留原始几何，保留交叉口与业务锚点；平行道路仅保留最快走廊。行程和执行段来自同一图，封路同步关闭相同反向几何的反向段。

**边界**：快照是2026年当前OSM，不是2024灾害时路网。业务点吸附到附近独立节点，最大偏移约3.77公里，界面逐点列出；不表示真实站址。速度按类别设定10—60km/h，每段向上取整到分钟；未处理转向限制、条件通行、车辆尺寸、灾害损伤或实时交通。无人机仍沿研究路网移动，不是飞行规划。不能当作救援导航。

OSM数据 © OpenStreetMap contributors，依据 [ODbL 1.0](https://www.openstreetmap.org/copyright) 使用；原始快照和派生几何保留署名与数据许可。

## 验证与研究边界

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m disaster.v2.evaluation --seeds 20 --budget 0.25 --sensitivity
python scripts/browser_v2.py
```

浏览器验证需按V2说明安装Playwright，会重置演示。新增验证覆盖迁移、双时钟、源失联、多步误差独立重算、过期输入、非周期P1/增援、资源故障、OSM单行方向和封路。

实验仍采用模拟基线路网，标准场景加20种子，每场景8配置（4方法加4个额外稳定权重）。OSM通过独立集成测试，不把模拟图对比标成OSM实验。每分钟审计身份、剩余路径可达、协同需求与同步。Gini只反映已开始任务的等待差异，须结合未满足需求；优化目标没有公平项。原负结果保留。

本次43项测试通过；168条执行记录的逐分钟约束审计违规数为0。敏感性结果：

| 配置 | 平均完成任务 / 12 | P1完成率 | 平均累计分配变更 |
|---|---:|---:|---:|
| 贪心 | 12.00 | 100.0% | 36.00 |
| 静态 | 3.57 | 32.4% | 9.00 |
| 动态 λ=0 | 11.67 | 97.1% | 49.05 |
| 动态 λ=5 | 11.52 | 98.1% | 40.48 |
| 动态 λ=20 | 11.52 | 97.1% | 39.90 |
| 动态 λ=50 | 11.52 | 97.1% | 39.86 |
| 动态 λ=100 | 11.57 | 97.1% | 39.76 |
| 动态＋规则前置 | 11.52 | 97.1% | 43.76 |

这里的“变更”是所有轮次分配对称差之和，也包含任务完成后的正常移除，不是纯粹的可避免改派。当前目标只惩罚迟到，没有奖励期限内更早开始，因此存在同目标值但出发时间不同的计划；这是解释贪心更早响应的一个机制假设，不能仅凭本次对比作因果结论。权重敏感性没有改变“当前场景贪心更好”的结论。
