# V2 本机应急研究工作台

本文保留V2说明；当前V2.1新增时效、多步评估、OSM与事件触发，最新边界及结果路径见 [README-V21.md](README-V21.md)。

按工作区参考图实现六个页面：总览、数据中心、风险预测、资源调度、策略决策、事件复盘。前端为独立 HTML/CSS/JavaScript，FastAPI 提供共享服务，SQLite 保存观测、任务、资源、计划及历史快照。仅监听本机，不需要公网部署。

## 启动

已有本机环境直接运行 `./run-v2.ps1`，访问 http://127.0.0.1:8800 。API 文档在 http://127.0.0.1:8800/docs 。仅启动一个服务进程，避免多个进程同时持有不同的内存态势。

新环境需要 Python 3.11 和 Node.js/npm：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-v2.lock.txt
npm --prefix frontend ci
.\.venv\Scripts\python.exe scripts/prepare_frontend.py
.\run-v2.ps1
```

首次启动自动将 `data/v2/raw/*.csv` 入库并拟合三个轻量预测基线。前端脚本和图表库由本机提供；OpenStreetMap 底图需要网络，断网仍可操作模拟节点、风险圈与路网。SQLite 文件、密钥和运行日志不进入 Git。

## 操作演示

1. 数据中心查看四类模拟观测、源资料、字段校验和去重结果。JSON 导入格式与 `/api/state` 的 `observations` 相同；时间戳须含时区，并与相对 2024-08-03 09:00 +08:00 的分钟一致。
2. 风险预测切换 Persistence、AR、Gradient Boosting，查看四类曲线和时间顺序留出误差。
3. 资源调度点击“重新优化”；选择道路注入中断，查看路径和任务变化。
4. 策略决策输入灾情，解析后核对地点、人数和需求，再确认生成任务；What-if 在状态副本上推演，不提交执行。
5. 每次推进 10 分钟会更新观测、任务释放、资源位置和计划；第 40 分钟增援可用。模拟数据截至第 180 分钟。
6. 事件复盘可读取、导出历史快照，或重置演示。重置保留历史版本。

## 模型配置

在启动服务的 PowerShell 中设置 `DISASTER_API_KEY`、`DISASTER_BASE_URL`、`DISASTER_MODEL`，再启动或重启服务。配置沿用主 README 的兼容 Chat Completions JSON 接口；`.env` 不会自动加载。未提供密钥时使用明确标注的离线规则，尚未完成真实提供商调用验收。

模型仅生成候选字段；服务校验字段结构、人数原文、时间、节点和道路编号，人工确认后才更新状态。API 失败和非法输出不会提交事件。条款检索为中文字符 TF-IDF 与 LSA 潜在向量融合，当前没有接入 BGE 或向量数据库。返回条款均带原文、章节、发布时间和来源链接。任务保存检索条款编号；原则性条款不自动变成硬约束。

## 模型与数据范围

- 10 个模拟地理节点、16 条道路、26 项资源、7 类资源、12 项复合任务。资源含无人机，作为 V2 异构资源扩展；全部位置、人数、能力、耗时和时限是实验设定。
- 三站点、四类观测由固定种子生成。预测模型只用场景零时刻之前的数据训练。误差表是 **5 分钟单步留出验证**；界面的 60 分钟曲线是递归预测，不能用单步误差宣称其准确率。
- 风险是固定权重的归一化指数，不是灾害概率。达到实验阈值时可提出搜救队、无人机前置任务；前置不产生实际灾情。
- 调度用 CP-SAT circuit 建立资源任务序列与相邻任务行程，复合任务要求所需资源同时到场。已锁定任务保留承诺；封路影响剩余路线时撤销尚未开始的协同任务，从最后到达节点重新安排。
- V2 采用可调加权目标：优先级缺口权重 10000/2000/300、迟到权重 10、行程权重 1、分配变化权重默认 20。这是加权折中，**不同于 V1 的顺序优化**。默认每轮求解预算 4 秒；无可行解时采用同样约束检查的贪心降级，界面明确显示。
- 公开通报仅进入案例资料库，晚公开事实不进入当前模拟决策。原始全文尚未完整归档，本地保留已核对节选和来源状态。不能据此声称还原康定真实指挥过程。

## 验证与结果

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m disaster.v2.evaluation --seeds 20 --budget 0.25
```

新版实验为标准场景和 20 个扰动种子 × 4 种方法，共 84 条结果：贪心、初始静态计划、动态重规划、动态加预测前置。共享多资源约束、扰动输入和执行器，观察至第 120 分钟。实验为了快速复现采用每轮 0.25 秒预算，具体参数与指标定义保存在 `results/v2/experiment_config.json`；不将其与默认 4 秒界面求解混为一谈。

`results/v2/dispatch_metrics.csv` 保存执行指标，`forecast_metrics.csv` 保存实测预测误差。未预设动态或预测前置胜出；机器负载会影响耗时和超时解。V1 的 63 条实验仍保留于 `results/metrics.csv`，两代场景不能直接横向比较。

本次 84 条执行记录约束违规数为 0；35 项单元/集成测试通过。21 个场景的实际结果均值：

| 方法 | 第120分钟完成任务数（共12项） | 紧急任务完成率 |
|---|---:|---:|
| 贪心 | 12.00 | 100.0% |
| 初始静态计划 | 3.57 | 32.4% |
| 动态重规划 | 11.57 | 97.1% |
| 动态＋预测前置 | 11.52 | 96.2% |

当前设定下贪心表现更好，预测前置没有带来整体收益。上述结果只描述所列模拟场景和预算，不证明现实救援效果或普遍算法优劣。
