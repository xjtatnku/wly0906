# V2.2：预测驱动应急资源调度

保留六页工作台，细化“多源观测 → 联合预测 → 区域风险排序 → 滚动调度 → 执行与追踪”。本版增加真实历史环境输入、优先级加权响应目标、多区域前置与资源紧缺实验。仅在本机运行：http://127.0.0.1:8800 。

已完成58项自动化测试、960组调度对照、20组消融和6组压力测试。完整数值、资源敏感性图及未胜出的结果见 [实验结果](docs/results-v22.md)。

## 启动与演示

已有环境运行 `./run-v2.ps1`。新环境使用 Python 3.11、Node.js/npm：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-v2.lock.txt
npm --prefix frontend ci
.\.venv\Scripts\python.exe scripts/prepare_frontend.py
.\run-v2.ps1
```

数据快照随仓库提供，启动不需要重新下载。SQLite 首次启动自动建立；只运行一个服务进程。底图瓦片需联网，断网时本地道路、节点、计划与图表仍可用。

1. **数据中心**：选择模拟三站四变量，或真实历史三点两变量；选择规则归一化或历史经验分位。应用会重置当前实验、保留历史快照。观察来源、时效、缺失率与质量。
2. **风险预测**：切换采样点及 Persistence / AR / Gradient Boosting。模拟数据评估 5/15/30/60 分钟；真实历史数据评估 60/180/360/720 分钟。误差按变量分别显示。
3. **资源调度**：优化后查看地图和行程/作业时间轴；调整响应权重 β，注入封路、故障，或推进到新增 P1、增援时刻。页面底部解释数据、预测、触发和方案变化。
4. **策略决策**：输入灾情，核对原文、候选及预案。可修改地点、人数和任务类型，批准后生成任务；拒绝也保留审计记录。模型密钥配置沿用 [V2说明](README-V2.md#模型配置)。未配置时明确使用离线规则，不能声称真实模型调用已经验收。
5. **事件复盘**：读取历史决策、导出状态；按资源比例和事件强度查看配对实验，下载预测、调度、消融及压力测试 CSV。V2.1 旧结果另表保留。

## 真实历史数据的范围

2024-07-20 至 2024-08-05 UTC，三个查询点：S01=(30.15,102.15)、S02=(30.05,102.25)、S03=(30.15,102.25)，顺序为纬度/经度。它们是产品网格采样点，**不是现场传感器站**；返回网格坐标保留在记录中，不能把查询坐标当作实际观测站址。

| 层 | 文件 | 内容 |
|---|---|---|
| Bronze | `data/bronze/environment/` | NASA/ERA5 HTTP 原始字节与 manifest：URL、参数、下载时间、SHA-256、来源、许可 |
| Silver | `data/silver/environment_native.json` | 3,672 条原生记录：2,448 条半小时 GPM 降雨率、1,224 条小时土壤水分 |
| Gold | `data/gold/environment_hourly.json` | 2,442 条小时联合输入，407 时点 × 3 点 × 2 变量 |
| 状态 | 本机 SQLite | 模式、预测、任务、资源、计划与决策追踪快照；历史观测本身读取已核验 Gold 文件 |

GPM 使用 NASA 官方 EGIS 的 IMERG Final V07 网格样本；每 6 小时查询并核对完整的 3×12 个采样键。初次按日查询出现服务截断，其 17 份响应保留作为采集审计，但构建器明确排除，不参与 Silver/Gold。ERA5-Land 通过 Open-Meteo 历史接口取得，参数显式指定 `models=era5_land`，避免混入其默认“最佳匹配”模型。获取的是点位服务响应，未声称下载完整全球 HDF/GRIB 产品。

土壤体积含水率由 0—1 转成百分数。每个整点的降雨只积分此前两个**已结束**的半小时段，折为上一小时平均降雨率；与该整点土壤值对齐。无效值不进入联合面板，没有伪造水位、位移或五分钟实测数据。

**这是事后环境研究回放。** IMERG Final 使用事后卫星/雨量计处理，NASA 说明其约在观测月份结束后 3.5 个月提供；ERA5-Land 是再分析。`received_at` 保留本次实际下载时间，`received_minute` 在此模式表示观测时钟上的实验释放时间，不是2024年真实发布时间。因此只能评估这些历史最终产品上的序列预测，不能证明当时的在线预警能力。政府通报仍按其真实公开时间管理，两种语义不混用。

来源：[NASA IMERG Final 产品页](https://gis.earthdata.nasa.gov/portal/home/item.html?id=cfa9a890b89b49d884871567844e9080)、[ERA5-Land 官方数据集](https://cds.climate.copernicus.eu/datasets/reanalysis-era5-land?tab=documentation)、[Open-Meteo 历史接口](https://open-meteo.com/en/docs/historical-weather-api)。NASA 产品 DOI：10.5067/GPM/IMERG/3B-HH/07。ERA5-Land 数据归属 Copernicus/ECMWF，接口数据同时注明 Open-Meteo；manifest 保存许可与署名信息。

## 预测与风险

把三个采样点全部可用变量拼成一个向量，再构造 12 阶滞后。模拟输入 144 维，真实小时输入 72 维。AR 为 StandardScaler + 多输出 Ridge；GB 为多输出 HistGradientBoosting；Persistence 保持各变量最近值。

场景第0分钟前的历史按时间75%/25%分割，固定训练段，从留出段的共同起点递归12步，禁止用真实中间值填入预测窗口。完成验证后，用全部场景前历史拟合在线实验模型。模型不随场景推进重新训练。144条模拟误差和72条真实误差分表，时间、变量、单位、训练样本、共同起点和特征数均可核对。

规则模式保留原实验阈值，并按可用变量重新归一化权重。经验模式使用场景前训练历史的经验分位；没有灾害标签，没有训练灾害发生概率。各区域以未来12步的最大排序分数作为前置权重。S01/S02/S03 对应 N4/N5/N8 是人工实验映射，不是已学习出的地质关系。最近12个联合时点存在缺口，或最新联合观测超过3个采样间隔时，暂停预测前置。

## 调度与前置

主调度目标：`J = U + βR + 10L + T + λC`。默认 β=10、λ=20。

- U：未安排任务按 P1/P2/P3 分别罚 10000/2000/300；单位是加权任务缺口。
- R：已安排任务的 `Σ w(priority) × (start − release)`，w=5/3/1。未安排任务 R=0，其代价在 U 中报告。
- L：已安排任务的迟到分钟之和；T：各资源计划行程分钟之和。
- C：每个旧计划中仍可执行的资源承诺是否改变，按资源计一次。首次分配、新任务附加、正常完成及已经锁定的动作不计入；仍有旧任务但换任务计改派，旧承诺全部撤销计撤回。

这是加权折中，**不是词典序保证**。期限内早到现在也会影响目标；并不保证每个场景或每个指标都比贪心好。程序重算目标分项与分配关系，决策追踪保留可核验数字。不同轮次输入或时刻可能改变，不直接相减其目标值。

多区域前置在主任务求解后进行，只选择当前整个窗口没有使用、已经可用且没有活动任务的搜救队/无人机。目的地可留在原地，或选 N4/N5/N8。情景为低（概率0.4、无新增需求）、中（0.4、普通协同搜救权重1）、高（0.2、P1权重2，并封闭最高排序区域的一条相邻道路）。概率和权重都是实验设定。

前置最小化各候选区风险权重×情景期望响应代价，加每分钟前置行程50的机会成本代理；选中计划必须优于原地不动，否则不移动。情景成本逐项输出，可验证其加权和。候选区分别用最近搜救队和无人机的较慢到达值评价，**没有建模多个候选区同时到来时的容量补救分配**，不能称为完整两阶段随机规划、SDDP 或灾害需求预测模型。前置的预计成本下降不等于实际救援收益。

沿用复合任务同步、资源序列、执行锁定、道路可达与故障排除约束。界面默认求解预算4秒，实验使用0.2秒；启用前置时主求解分配80%预算，剩余预算供前置，前置最多0.6秒。预算针对求解器，端到端延迟还包括建模和验证。无可行解使用经相同约束检查的贪心降级，状态明确报告。

```powershell
$env:OMP_NUM_THREADS='1'
$env:OPENBLAS_NUM_THREADS='1'
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m disaster.v2.research --seeds 20 --budget 0.2 --workers 4
# 同一代码与参数下中断续跑：追加 --resume
```

`results/v22/` 包含：

| 文件 | 实验定义 |
|---|---|
| `forecast_synthetic.csv` / `forecast_historical.csv` | 三模型、三采样点、全部可用变量、四个原生时距；真实与模拟分表 |
| `scheduling.csv` | 20种子 × 4资源比例 × 3事件强度 × 4方法 = 960条 |
| `ablation.csv` | 20种子，固定50%资源/高事件强度，β=0；与主表同种子的 Rolling β=10 配对 |
| `stress.csv` | 封路、新P1、资源故障、延迟数据、增援、同刻多事件，共6条，含触发时追踪 |
| `experiment_config.json` | 参数、范围、指标口径与输入摘要 |

资源比例100/75/50/35%，每类型取 `max(1,floor(n×比例))` 个资源，实际总数另列，因此并不等于总资源数精确乘比例。低/中/高分别12/24/36任务；增加事件保留原12项基础任务。所有方法共享同种子路程扰动、任务、资源、因果预测与执行器。第20分钟关闭RD00，第120分钟截断，每分钟约束审计。

贪心复用零求解预算下的约束一致降级策略，`fallback_calls` 因而包括贪心的**刻意调用**；Static只在第0分钟分配，是偏弱基线；Rolling与Rolling+Forecast均响应事件和周期触发。响应只统计已实际开始任务，必须同时看完成率、未满足需求和开始任务数。行程统计实际执行占用分钟，包含被中断的部分行程，不累计尚未走完的未来路线。

公平指标先按区域求已开始任务平均等待 Wz，再计算区域间 Gini；没有开始记录的区域不填0，另报 `unserved_regions` 和各区任务/未开始数量。不能用低Gini掩盖未服务区域。资源故障中断的任务按重新开始记录评价，不是人员首次获救时间。

压力事件发生在非周期第17分钟。延迟情景冻结数据接收到第-5分钟；同刻多事件采用同一执行服务的连续事件操作，报告包含这些操作的总延迟，不声称一次原子批处理。墙钟耗时、超时可行解和个别指标可能随机器与并发负载变化，固定输入不等于逐位相同的超时解。

浏览器验证使用系统 Python 的 Playwright：`python scripts/browser_v2.py` 与 `python scripts/browser_v22.py`；需要先启动服务并安装 Chromium。这两条脚本会重置本机演示并保留快照，不用于生产环境。截图和浏览器验证记录保存在同一结果目录。

## 解释边界

任务、资源、速度、优先级、时限、封路和灾情阶段仍是模拟设定。OSM几何是真实快照，但不是2024历史路况；仍有业务点吸附、速度和车辆限制等边界，见 [V2.1说明](README-V21.md#osm寻路)。无人机仍沿研究路网移动。

既有 [研究依据](docs/research-v21.md) 保留；本版借鉴动态滚动决策、区域公平评价和预测情景思想，不声称复现 A-DREAM、Bhattarai & Song 或 CrisiSense-RAG 的算法和结论。V1/V2/V2.1原结果均保留；重跑旧版本实验需切换对应基线分支，避免把新优化器生成的结果误标成旧版。
