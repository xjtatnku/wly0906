# 问题、模型与接口

## 研究问题

当任务、道路与可用队伍发生变化时，如何保持已执行动作一致，在有限资源条件下优先满足紧急需求，并保留可核查的决策依据？研究原型把信息解释与数值调度分开：模型处理候选信息，程序维护状态与约束。

状态 S(t) 包括当前模拟分钟、道路可通行性、队伍最近到达节点/在途边/剩余行程/作业结束时刻、已知任务、已完成需求与已处理事件。事件更新与每5分钟的决策机会触发求解；模拟步长1分钟。

## 单轮分配

对当前可用队伍 i 和尚有缺口任务 j 建立 x(i,j)∈{0,1}。只为能力匹配且当前路网可达的组合建立变量，路网边权是正整数分钟。

- 每队伍至多一个任务：Σj x(i,j)≤1。
- 每任务分配不超过缺口：Σi x(i,j)≤required(j)−completed(j)−committed(j)。
- 执行中和未到增援时刻的队伍不进入决策变量。

四级词典序目标依次为：紧急缺口、普通缺口、已分配队伍的预计迟到分钟总和、行程分钟总和。程序等价地最大化前两级的新增满足量，再最小化时间目标。每级最优值作为下一轮约束，整个调用共享5秒预算；未证明某级最优时不继续下一级。可行解、超时保留解和贪心降级分别标记。

优先级只有紧急1与普通2，是实验设计；不等同于政府应急响应等级。每支队伍独立完成一个需求单位，多支队伍需求允许分批到达和完成。作业不具有强制同时开工语义。

## 执行语义

派遣后队伍逐边行进，到节点才更新位置，抵达任务地点后开始固定时长作业，完成后可再次派遣。每轮只分配下一项任务，不预约未来队列。

道路阻断若影响在途计划，回到最近已到达节点的离散状态重新找路，之前消耗的时间保持不变。无路可达时取消该队伍的未完成承诺，队伍在最近节点变为空闲，对应需求重新开放。已经作业的队伍不受其他道路变化影响。

事件先验证再整体提交；重复ID不产生副作用。已确认事件不能倒退时间。重置会创建全新场景，不修改旧日志中的历史动作。

## 公共接口

| 接口 | 输入 | 输出/作用 |
|---|---|---|
| `extract_event(text,state,live)` | 原文、已知节点、调用模式 | candidate/mode/error；不修改状态 |
| `Retriever.search(query,k,as_of)` | 查询与知识截止时间 | 带ID、分数、原文、版本、范围的条款列表 |
| `suggest_task(candidate,hits,state,live)` | 候选与检索条款 | 引用ID和解释；不决定调度数量 |
| `build_event(...)` | 人工确认的节点、能力、数量、时限 | 幂等事件对象 |
| `apply_event(state,event)` | 经校验事件 | 提交变更，返回是否为新事件 |
| `solve(state,method,time_limit)` | 当前状态、算法与预算 | assignments/status/seconds/optimal_levels |
| `dispatch(state,decision)` | 求解结果 | 再次校验后提交派遣 |
| `advance(state,until,method)` | 目标模拟分钟 | 行进、作业、资源释放与周期重规划 |
| `metrics(state)` | 执行结果 | 满足率、缺口、响应/迟到、完成数、求解耗时 |

派遣对象含team、task、path、travel、arrival、late。接口校验能力、唯一占用、任务容量、道路连通、行程/到达数值。模型解释只允许选择受限理由代码，最终数字、队伍及任务关系由程序渲染。

## 评价与可解释性边界

每次派遣通过约束校验，模拟每步断言不超配、能力匹配；违反时实验直接失败，不静默累积错误。正常结束的violations为0。代码保留该指标用于汇总，但不能据此宣称覆盖现实全部安全条件。

未派遣可能源于能力缺失、暂时占用、未到增援时间或道路不可达。页面展示队伍、任务缺口、道路和日志供核查。预案解释不是优化器最优性的证据；最优性只针对本轮明确写出的四级目标。

实验不含大模型任务生成输出，以固定结构化输入隔离算法差异。NLP模块独立评估，避免把人工确认效果归因于模型。实际模型评估必须使用真实API并记录模式。
